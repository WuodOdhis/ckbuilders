# Week 9: Turning the launch_token Fixture Into a Real Builder Step

**Dates:** June 24, 2026

This week was about cleaning up the `launch_token` path from Week 8. Last week I
proved that a CellScript launch transaction could be accepted on local devnet,
but the script was still too hand-wired. It worked more like a fixture than a
builder someone could safely demonstrate.

The goal this week was to make the first AMM-builder step cleaner, repeatable,
and easier to explain.

## What Changed

I updated the local CellScript toolchain to `v0.16.2`:

```bash
cellc --version
# cellc 0.16.2
```

The important change in this version is that the compiler now gives builders
more of the information they need instead of forcing us to guess.

The key commands are:

- `cellc resource-identity`, which creates passive resource type identities
- `cellc builder manifest`, which describes what a transaction builder must produce
- `cellc builder check`, which checks a candidate transaction before signing
- `cellc entry-witness`, which generates the witness bytes the on-chain script expects

In simple terms, I stopped treating the builder as something that should invent
the transaction format by hand. The builder should ask `cellc` for the contract
between the off-chain code and the on-chain CellScript program.

## The Main Bug

The biggest issue was not in CellScript. It was in my builder code.

The launch transaction kept failing with CellScript error code `3`, which means
the script loaded some cell data or field and found something different from what
it expected.

The problem was how the builder calculated CKB script hashes. I was hashing this
kind of simplified data:

```text
code_hash || hash_type || args
```

But CKB does not hash scripts that way. CKB hashes the Molecule-packed `Script`
structure.

That mistake affected two important values:

- the creator lock hash used by `with_lock(...)`
- the pool type hash stored inside `LPReceipt.pool_id`

After fixing the hash calculation to use the proper CKB packed script format,
the CellScript validation error disappeared.

## Clean Builder Script

I then turned the working diagnostic script into a cleaner devnet builder script
inside the public repo:

```text
https://github.com/WuodOdhis/cellscript-swap-builder
```

New script:

```text
scripts/build_launch_tx.py
```

The script now does the practical builder work:

- loads output type scripts from the compiler-generated resource identity plan;
- reads the paired funding token from a live devnet cell;
- generates the raw CellScript witness with `cellc entry-witness`;
- builds the expected `launch_token` outputs;
- dry-runs the transaction against local CKB devnet;
- only submits if I explicitly pass `--submit`.

The safe default matters because submitting would consume the current launch
funding cell. For demos, dry-run is enough to prove the transaction is accepted
by the script without spending the cell.

## What This Means

The project is now demo-ready for the first step of the AMM flow.

It can show:

- CellScript source compiled into a real CKB script;
- compiler-generated resource identities used by an off-chain builder;
- canonical witness bytes generated by `cellc`;
- a launch transaction that passes CKB devnet dry-run;
- a safe path where submission is explicit, not accidental.

This is not a finished AMM app yet. It does not complete `mint_with_authority`,
`seed_pool`, or `swap_a_for_b`. But it proves the most important foundation: the
builder can now construct a real CellScript-validated launch transaction using
compiler-supported metadata instead of one-off fixture assumptions.
