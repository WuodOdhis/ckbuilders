# ckb2023 Hardfork Changes

The ckb2023 hardfork introduced several breaking changes that affect transaction construction and validation.

## Occupied Capacity

**Before:** Each cell needed minimum capacity based on `ceil(serialized_size / 10000) * 10^8` shannons. A 14KB cell cost ~2 CKB.

**After:** Each byte costs 1 CKB. `occupied = ceil(serialized_bytes / 64) * 10^8` (with 64-byte alignment). A 14KB cell costs ~14,153 CKB.

This makes deploying large contracts expensive. The `amm_pool.elf` (36KB) costs 36,780 CKB.

## Sighash Changes

The secp256k1 lock script changed how it computes the sighash. Pre-ckb2023 it prepended `"Nervos Message:"` to the message before hashing. Post-ckb2023 it uses the raw sighash directly.

If your SDK uses the old format and the node uses the new format (or vice versa), signatures fail with error -31.

## Minimum Cell Capacity

The minimum cell capacity increased from 61 CKB to account for the new byte-based pricing. Always_success cells with empty data now cost ~61 CKB minimum.

## Dep Group Changes

Dep groups (cell deps with `dep_type = "dep_group"`) now resolve differently. The group cell's data must be a list of outpoints in molecule format. Some older deployments stopped working.

## Migration Path

1. Update `occupied_capacity` calculations to use byte-based pricing.
2. Verify the sighash format matches the lock script version.
3. Test against a devnet with `ckb2023` enabled from epoch 0.
